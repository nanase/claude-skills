# design-options — 見た目の案を並べて人に選ばせる

デザインを決める段で、案を 1 枚のページに並べて公開し、人に選ばせる。選ばれた案と理由を残すところまでを担う。実装はしない。実装後の突き合わせもしない。

好みが入る判断は test も AI レビューも決められない。だから案が並んだ時点で人へ渡す。ページの作り込みは扱わず、案を並べて選ばせる形だけを扱う。

## 発動するか — 案が 2 つ以上あって、好みが判断材料になるときだけ

見た目の話かどうかでなく、選ばせる価値のある案が並ぶかで決める。

- どれも成立する案が 2 つ以上ある → 発動して並べる
- 次はいずれも発動しない
  - 仕様どおり・唯一解・既存画面に倣うだけ
  - 実物を起動して見せられ、並べる案が他にない
  - 操作感・遷移・アニメーションが判断材料
    - 静止画では測れないので実物で見せる
- 迷ったら発動する

## 案を絞る

人へ出せる選択肢は 4 つまでとなる。現行を並べるなら、その 1 枠も使う。案は 2〜3 に絞る。

絞れないときは、聞く軸を 1 つに限って回数を分ける。例えば、配色を決めてから余白を決める。

## 比較の土台をそろえる

案ごとに変えるのは、比べたい 1 軸だけとする。文言・データ・幅・状態はそろえる。土台が違うと、何を選んだのかが後から分からなくなる。

- 実寸で並べる
  - 縮小して詰め込まない
- 背景色を案ごとに指定する
  - ページは閲覧者のテーマで描かれる
  - 指定しないと、見る人ごとに比較結果が変わる
- 案に A 案・B 案 のラベルを振る
  - 後で出す選択肢と一字一句そろえる

## 画像の形式を選ぶ

色を判断材料にするなら、可逆形式で撮る。PNG か WebP lossless を使う。UI のスクリーンショットでは WebP lossless が PNG より小さくなる。

JPEG は彩度の高い細い縁・文字・境界を崩す。特に赤が潰れる。撮った後に PNG へ変換しても戻らないので、撮影の時点から可逆にする。

写真の雰囲気を比べるだけなら JPEG でよい。容量でも有利になる。

外部の画像は読み込めないため、ページへ埋め込む。base64 で約 1.33 倍に膨らむ。ページ全体で 16MB を超えられない。枚数が多いときは、色を見る画像だけ可逆にする。

## URL を変えない

同じ検討は、同じファイルパスへ書き直して再公開する。パスを変えると別の URL になり、貼ったリンクが古い案を指したままになる。

- 案を差し替えても URL は変えない
- 版の違いは label と note に残す
- アイコンは最初の公開でだけ指定する

## 選ばせる

公開したら URL を添えて `AskUserQuestion` で尋ねる。提示だけで終えない。

```text
3 案を並べました: <URL>

どれで進めますか。
```

- 選択肢は案のラベルをそのまま使う
- 自由記述の枠を自分で足さない
  - 既定で「Other」がある
  - 折衷の指定はそこで受けられる
- 1 問で終える
  - 案の比較だけを聞く

## 決定を残す

選ばれたら、Issue / PR に 1 行残す。URL・選んだ案・その理由を書く。会話しか残らないと、後から理由を辿れなくなる。

```text
配色: B 案（アクセントを橙）を採用 … 既存のバッジと衝突しないため / <URL>
```

## 外へ出す前に確かめる

ページは既定で非公開だが、手元から出て claude.ai 上に置かれる。未公開の画面・顧客のデータを載せるときは、出してよいかを先に確かめる。
