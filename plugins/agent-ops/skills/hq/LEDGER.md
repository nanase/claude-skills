# 台帳と待ち受け

子からの報告と、人へのお願いを台帳に 1 件ずつ持つ。人の操作・マージ・クローズ・セッションを閉じたことは、監視スクリプトで検知する。ユーザーからの「打った」「マージした」の連絡を待たずに進めるためである。

台帳は [HANDOFF_STORE.md](HANDOFF_STORE.md) と同じ `.claude/handoff/` の下にあり、git の管理外である。HQ を立て直しても、台帳を読めば続きから進められる。操作は `scripts/ledger.sh` に任せ、ファイルを手で書き換えない。使い方はスクリプトの冒頭にある。

スクリプトは Linux で動く前提である。プロセスの生死を `/proc` で見て、Claude Code がセッションごとに置く登録簿（`~/.claude/sessions`）を読み、`flock`・`jq` を使う。これらが無い環境では台帳と見張りを使わず、人と子からの「打った」「マージした」の連絡で進める。

## 通し番号

| 番号 | 振る対象 | 振るとき |
| --- | --- | --- |
| S | 子セッション | ハンドオフを発行する前 |
| R | 子からの報告のうち、人に見てほしいもの | 受けたとき |
| U | 人に打ってもらうコマンド | 🙋 を受けたとき |

- 番号は使い回さない
  - 解決したものの番号も、別の件に充てない
- 番号は保管先全体で一意である
  - 台帳を分けた HQ どうしでも重ならない
- S は `ledger.sh next S` で取る
  - R と U は、台帳へ足すと同時に振られる

## 報告（R）

子から届いた報告・質問・申請のうち、人に見てほしいものを R として台帳へ足す。詳細はチャットへ出さず、台帳に書く。

- R にするのは、人の判断・確認が要るもの、人が知らないと困るもの
  - HQ がその場で片付けたものは R にしない。Ready の許可・見送り、レート制限の待ちが該当する
  - 片付いたものは一覧に出ないため、R にしても人の目に触れない
- 詳細は `ledger.sh add R <S番号> <見出し>` の標準入力へ渡す
  - 子の言葉を要約せずに写し、HQ の見立てを添える
  - 見出しは 1 行で、何の件か分かる形にする
- 人が「R3 について教えて」と言ったときだけ、`ledger.sh show R3` で読んで詳細を出す
- 解決したら `ledger.sh set R3 done` とする
- 子が人の判断を待って止まっているものは `ledger.sh set R3 wait` とし、一覧で ⏸ が付く
  - 子の画面で人の確認を待っているときが該当する。人はその子の画面へ行けば進められる

## 人へのお願い

人へのお願いは、次の 4 種類を台帳に持つ。報告の「お願いしたいこと」には `ledger.sh list ask` の出力をそのまま貼る。

| 印 | お願い | 足すとき | 足し方 |
| --- | --- | --- | --- |
| 🙋 | コマンドを打つ | 子から 🙋 を受けたとき | `add U <S番号> <見出し> -C <場所> -- <コマンド>` |
| 🔀 | PR のマージ | 子からマージ待ちの連絡を受けたとき | `add merge <S番号> <PR番号>` |
| 🔒 | issue のクローズ | クローズしてよいと判断したとき | `add close <S番号か -> <issue番号>` |
| 🧹 | セッションを閉じる | 子の完了報告を受けたとき | `add cleanup <S番号> <セッション名>` |

- 🙋 の場所は、子が書いてきた「実行する場所」から決める
  - HQ と同じ環境なら `-C` に絶対パスを渡す。worktree で打つものも、worktree の絶対パスを渡す
  - HQ からファイルが見えない別の環境（コンテナの外のホスト PC など）なら `--host` を渡す。ファイルが見えないため検知できず、従来どおり人の「打った」の連絡を待つ
- 🙋 のコマンドはラッパー `run.sh` を通す形になる
  - 出力をログへ写し、終了コードをファイルへ書く。どちらも保管先の `runs/` に集まる
  - パイプや `&&` を含むコマンドは、`-- bash -c '…'` の形で渡す
- 🧹 のセッション名は `ListAgents` の名前（`myapp-b7` など）を渡す
  - 登録簿から pid を引いて持つため、後で名前が変わっても追える

## 待ち受け

`scripts/watch.sh` が台帳の 🙋・🔀・🔒・🧹 を見張り、どれかが片付いたら 1 行ずつ出して終わる。HQ は Bash の `run_in_background` で走らせ、終わったときに起こされる。

- ターンを終える前に、`watch.sh --status` で見張りが動いているかを見る
  - `WATCH=stopped` なら、`watch.sh` を `run_in_background` で走らせる
  - `WATCH=running` と `WATCH=nothing` なら張らない。張っても見張りはすぐ終わり、HQ を無駄に起こす
  - `WATCH=nothing` は、見張れる対象が台帳に無い状態である。別の環境で打つ 🙋 だけが残っているときも、こうなる
- 走らせた後に台帳へ足したお願いも、見張りは次の 1 巡で拾う
- 起こされたら、出た行をすべて処理する
  - 処理し終えたら、上の手順で張り直す

出た行ごとの扱いは次のとおりである。

| 出力 | 扱い |
| --- | --- |
| `EVENT=U3 EXIT=0` | 依頼元の子へ、U3 が終わったことと再開してよいことを送る。`set U3 done` |
| `EVENT=U3 EXIT=<0 以外>` | `LOG=` のログを読んで原因を確かめる。`set U3 done` としたうえで、打ち直してもらうなら新しい U を振る。人の判断が要るなら R にする |
| `EVENT=merge-103 STATE=MERGED` | 担当の子へマージを伝え、Ready の枠を配り直す（[SKILL.md](SKILL.md)「レビュー枠を配る」）。`set merge-103 done` |
| `EVENT=merge-103 STATE=CLOSED` | マージされずに閉じた。担当の子へ伝えて止まるよう頼み、R にする。`set merge-103 done` |
| `EVENT=close-42 STATE=CLOSED` | 関係する子がいれば伝える。進捗率を出し直す。`set close-42 done` |
| `EVENT=cleanup-S9 SESSION=gone` | `ListAgents` からそのセッションが消えたことを確かめる。消えていれば `set cleanup-S9 done` とし、ハンドオフを片付ける（[HANDOFF_STORE.md](HANDOFF_STORE.md)） |
| `EVENT=none` | 見張る対象が無い。何もせず、張り直さない |

- 監視で検知できない 🙋 は、「打った」の連絡で片付ける
  - 別の環境で打つものと、人が子の画面から写して打ったものが該当する。後者は `run.sh` を通らない
  - 人から「U3 打った」と聞いたら、依頼元の子へ再開してよいことを送り、`set U3 done` とする
  - 人が U 番号でなく S 番号で伝えてきたときは、その S の未解決の U が 1 件なら、それを指すと読む。2 件以上なら、どれかを人に尋ねる
  - 子から「打った」と届いたら、その U を `done` にする
- U・🔀・🔒 が片付いたら、表の状態も合わせて更新する

## 台帳を分けるとき

同じ `.claude/handoff/` を別の HQ と共有するときは、`ledger.sh` と `watch.sh` の先頭に `-l <台帳名>` を付けて台帳を分ける。分けないと、相手の子のお願いで起こされ、片付けられないまま起こされ続ける。

- 台帳名は、HQ を立て直しても変わらないものにする
  - 担当する要件の名前などが該当する。セッション名は立て直すと変わる
- 立て直すときは、台帳名を引き継ぎに書く
