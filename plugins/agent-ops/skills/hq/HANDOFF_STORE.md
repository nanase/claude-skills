# ハンドオフの保管

発行したハンドオフは、本文をチャットへ出さずファイルへ書き出す。人へ渡すのは、見出しと推奨モデルの行、タイトル・パス・HQ のセッション名の 3 行だけとする。

ここは生きているハンドオフだけを置く投函箱であり、記録ではない。完了したタスクの記録は issue と PR に残るため、この保管先は捨ててよい。

## 置き場所

```text
.claude/handoff/
  .gitignore
  .done/
  0903-1432-auth-retry.md
  ledger/     台帳（LEDGER.md）
  runs/       人が打ったコマンドのログと終了コード
  counters/   S・R・U の通し番号
```

`ledger/`・`runs/`・`counters/` はスクリプトが作るため、手で用意しなくてよい。

- 初回だけ `.claude/handoff/.gitignore` を作り、中身を `*` の 1 行にする
  - git 管理するほどのものではないため
  - プロジェクト直下の `.gitignore` は書き換えない
- 初回に `mkdir -p .claude/handoff/.done` も行う
  - git 管理外なので clone しても現れず、無いと片付けの移動が失敗する
- ファイル名は `MMDD-HHMM-スラッグ.md`
  - 連番にしない。次の番号を知るために過去を読む必要が出る
  - タスクごとに issue を立てているときは `<issue 番号>-スラッグ.md` でもよい
- 発行した後にファイル名を変えない
  - 人が持っているパスの指す先が消えるため

## ファイルの中身

frontmatter を置き、その下にハンドオフの本文をそのまま続ける。

```yaml
---
title: S12 認証リトライの実装
sid: S12
issue: 42
session:
pr:
---
```

- `title` — 人へ渡す 1 行目に使う。頭に S 番号を付ける
- `sid` — 子セッションの S 番号。`scripts/ledger.sh next S` で取る（[LEDGER.md](LEDGER.md)）
- `issue` — 進捗の管理先
- `session` — 子の初回連絡を受けてから `名前 [ref]` の形で埋める
- `pr` — 子から PR 番号を受けてから埋める

## 人へ渡す 3 行

チャットには次の形で出す。見出しと推奨モデルの行はコードブロックの外に置き、人がコピーするのはコードブロックの 3 行だけにする。

````markdown
### 🚩 ハンドオフ: {title}

推奨モデル: Opus 系 — {理由}

```text
セッション名: {title}
.claude/handoff/{ファイル名} を最初に読み、その指示に従って着手してください。
HQ のセッション名は {HQ のセッション名} です。
```

子のセッション名に {sid} が残らなかったら、子のセッションで `/rename {title}` を打ってください。
````

- 🚩 の見出しは、他の報告に埋もれずに探せるようにするために付ける
- 推奨モデルの行は、Opus 系を勧めるときだけ書く。書かなければ、人は既定のモデルで子を立てる
  - モデルを選ぶのは人なので、コピーする 3 行には入れない
  - Opus 系を勧めるのは、後戻りしにくい設計判断を子が下す、複数の領域にまたがり読む範囲が広い、手本の無い新しい型を立てる、のように判断の重さや読む量が Sonnet 系では足りないと見たときである
  - モデルは版名でなく系統名で書く。版名は新しいモデルが出るたびに古くなる

- 1 行目は「セッション名: 」の後にタイトルだけを置く
  - 子セッションの表示名がここから決まる。頭に置いた S 番号が表示名に残りやすい
  - 残らなかったときは人が `/rename` で直せる。そのための案内をコードブロックの下に 1 行置く
  - `[HQ]` のような印は付けない。子にも貼り付ける人にも意味が伝わらない
- パスはリポジトリのルートからの相対パスとし、区切りは `/` にする
  - 子セッションはリポジトリのルートで始まるため、これで解決できる
  - 絶対パスは OS ごとに形が変わる
- 3 行目には、渡す時点で生きている HQ のセッション名を入れる
  - 渡す直前に「連絡経路」の手順で取り直した `name` を使う
  - ファイルの本文へは書かない
    - HQ 自身も別のセッションへ引き継がれることがある
    - 本文へ書いた宛先は引き継ぎ前の HQ を指したまま残る
    - 引き継ぎ前の HQ は `ListAgents` に現れないため、後から渡された子は送り先を決められず連絡が届かない
  - HQ が引き継がれたとき、`/rename` で名前を変えたときは、未実行のハンドオフの 3 行を新しい名前で渡し直す
    - 渡し済みの 3 行目は引き継ぎ前の HQ を指したままである
    - 子がまだ立っていないので、ファイルではなく 3 行を渡し直せば足りる
- 子への定型指示はファイルの本文へ入れ、この 3 行には入れない
- チャットへ出すのは、見出しと推奨モデルの行、この 3 行だけとする

## 状態は持たない

`status` のようなフィールドは置かず、実データから読む。二重管理にすると実体からずれるためである。

| 状態 | 読み方 |
| --- | --- |
| 未実行 | `.claude/handoff/` にあり、`session` が空 |
| 実行中 | `.claude/handoff/` にあり、`session` が埋まっている |
| 完了（閉じてよい） | `.claude/handoff/` にあり、台帳に未解決の 🧹 がある |
| 片付け済み・取り消し | `.done/` へ移っている |

未実行の一覧は次で取る。出力はファイル名だけである。

```sh
find .claude/handoff -maxdepth 1 -name '*.md' -exec grep -L '^session: .' {} +
```

glob を直接渡すと、0 件のときにパターンがそのまま `grep` へ届いてエラーになる。

## 発行済みを作り直すとき

- 未実行のものは、同じパスのまま上書きする
  - 人が持っているパスは変わらないため、渡し直してもらう必要はない
  - チャットへは更新した旨の 1 行だけを出す
- 実行中のものは、ファイルを更新したうえで担当の子へ知らせる
  - 読み終えた子にはファイルの変更が届かないため

## 片付け

- 完了報告を受けても、すぐには移さない
  - 人がそのセッションを閉じるまで、報告の表に「完了（閉じてよい）」として残すため
- セッションが閉じられたのを検知したら、そのファイルを `.done/` へ移す（[LEDGER.md](LEDGER.md)）
- 取り消したタスクのファイルも `.done/` へ移す
- `.done/` は読まない
  - 一覧もしない。人がいつ削除してもよい
- ハンドオフを発行するたびに、未実行の一覧を見る
  - ファイル名の日時が古いまま残っているものは、まだ渡されていないか、渡す必要が無くなっている
  - 心当たりが無いものはユーザーへ確認し、不要なら `.done/` へ移す
