# readable-japanese — 読みやすい日本語

日本語の文章を、読み手が引っかからずに読める状態に整える作法である。文体・語彙・記法の乱れを直す。適用対象はドキュメント、コード内のコメント、Issue、PR、コミットメッセージ、画面に出す UI の文言など、日本語を書く場所全般である。

## 手を入れない箇所

そのまま出力・使用される固定文字列は推敲しない。文言を変えると挙動や例の意味が変わるためである。

- コマンド・コード
  - 画面に出す文言は、コードの中にあっても対象に含める
- 出力テンプレート、サブエージェントへ渡すプロンプト
- わざと悪い例を見せている引用や before/after の例

## 語尾の統一

文書中で「です・ます」調と「だ・である」調を混ぜず、必ずどちらかに統一する。

## 体言止め

通常の文では体言止めを避ける。文末は述語で締める。要約やリード文、description のような説明文も通常の文として扱い、体言止めにしない。体言止めは次の箇所でのみ使う。

- タイトル
  - セクション名を含む
  - コミット名
- 箇条書き
- UI のボタン・トグル・メニュー・ラベル
  - 詳細は「UI の文言」

## 読点

日本語の読点は文法上の義務ではない。打つ所は次に限る。

- 節の切れ目
  - 「〜し、」「〜ので、」「〜が、」のように述語のまとまりが変わる所
- 長い修飾語が 2 つ以上並ぶときの境界
- 語順を入れ替えて、短い修飾語を前に出した所
- 「しかし」「ただし」「したがって」など接続の語の後
- 打たないと係り方を読み違える所

文節ごとには打たない。「〜は、」「〜を、」「〜と、」のように、主語と述語・目的語と動詞のあいだへ機械的に打つと文が細切れになる。

減らすときに節の切れ目まで消さない。「間引き、1 フレームに 1 回だけ反映する」から読点を消すと「間引き 1 フレーム」と誤って読まれる。

## 語彙

意味が合っていても、その種類の文書で使われない語は直す。判断はこの問い 1 つで行う。

> 同じ分野の日本語話者が、この語を口に出すか。

平易かどうかでは判断しない。専門語でも、その分野で日常的に使われるなら残す。

### 訳しすぎない

分野に定訳がある語は訳し直さない。定訳を崩すと、意味が通っても検索できなくなり、読み手が同じものだと気づけなくなる。

カタカナか漢語かは基準にならない。`引数`・`戻り値`・`既定値` は漢語のままの定訳で、`コミット`・`リポジトリ`・`カード` はカタカナのままの定訳である。どちらも訳し直さない。

定訳が無い語、揺れている語に限って、上の問いで選ぶ。漢語とカタカナのどちらも通る語（白色雑音とホワイトノイズなど）は、どちらでもよい。文書の中でそろえる。

### 直訳を持ち込まない

英語の語をそのまま置き換えて、日本語として浮いた語は直す。「平易な語に直す」ではなく「その分野の日本語文書に出てくる語に直す」と考える。平易さを目指すと、今度は訳しすぎる。

事例は [VOCABULARY.md](VOCABULARY.md) にある。プロジェクト固有の語は `.claude/NG.md` にあり、あれば併せて参照する。

### 溜める

気づいた語はその場で議論せず、`/readable:ng` で `.claude/NG.md` へ落とす。過去の推敲コミットからは `scripts/harvest.sh` で候補を拾える。範囲は引数で絞る。どちらも候補を出すだけで、仕分けは人が行う。

溜めた語は、そのままでは増えるほど効かなくなる。表が長いほど 1 行あたりの重みが下がり、表に無い語は止められないためである。溜まったら規則にまとめ直し、事例は VOCABULARY.md へ落として証拠として残す。

新しく捕まえた語が既存の規則で説明できるなら、足りないのは規則ではなく適用のほうである。規則を増やす前に、見直しの手順を疑う。

## 英語構文の持ち込み

語彙より目立たないが、量は多い。意味が通るので見落としやすい。

| 出がちな形 | 直した形 |
| --- | --- |
| X は Y を提供する | X で Y ができる |
| X は Y を持つ | X には Y がある |
| 〜することができる | 〜できる |
| それは / あなたは | 訳された代名詞は落とす |
| 〜が行われる | 〜する |
| 〜の一つ | 多くは削れる |

## 箇条書き

- 原則として体言止め
- 体言止めが不自然になるときは最小限の文を許容
  - 「〜しない」の形
  - 動作を「〜の破棄」「〜の停止と再開」と名詞にして体言止めにしない。「〜を捨てる」と述語で書く
- 末尾に「。」を付けない
- 装飾としての太字を使わない
- 1 項目に複数の文を詰めない
  - 収まらないときは入れ子にして分ける
  - 入れ子は 2 段までに留める
- 番号付きリストも同じく末尾に「。」を付けない
  - 順序を表すので、体言止めにせず「〜する」の述語形で書く

長い文を入れ子で分ける例を示す。

```text
元の文章:
- 妥当な指摘: 対応する。相違がなければ返答不要。
- 対応しない指摘: 理由を当該スレッドに返す。
- スコープ外修正: 別 PR を検討する。当該 PR で「ついで修正」しない。

読みやすい例:
- 妥当な指摘
  - 対応
  - 相違がなければ返答不要
- 対応しない指摘
  - 当該スレッドにて理由を返答
- スコープ外修正
  - 別 PR を検討
  - 当該 PR で「ついで修正」しない
```

## UI の文言

画面の文言は、短いラベルと文で書き方を分ける。英語の識別子やコメントを逐語訳しない。日本語のアプリで同じ役割の箇所に付いている語を選ぶ。

| 種類 | 書き方 | 例 |
| --- | --- | --- |
| ボタン・トグル・チェックボックス・メニュー・タブ | 体言止め。動詞の終止形にしない | 取り消し・並べ替え・複製・詳細設定 |
| 状態の表示 | 体言止め | 保存中…・完了 |
| メッセージ・確認・エラー・空の状態 | です・ます調の文。体言止めにしない | 「まだ録音がありません。」「この録音を破棄しますか？元に戻せません。」 |

文にしても短く保つ。元の文言にない語を足して丁寧にしない。「Drop images here or click to browse」は「画像をここにドラッグするか、クリックして選んでください。」とし、「ドラッグ＆ドロップ」「ファイルを」を足さない。

語は画面を使う人の語にする。開発者や業界の符丁のカタカナ語は、定訳であっても画面に出さない。「テイク」は「録音」、「スクラブ」は「再生位置を移動」とする。「訳しすぎない」の規則は開発者が読む文書に当てはめ、画面では使う人が口に出す語を優先する。

## 括弧の使用

括弧は必要最小限に留める。読み手が見落とすと困る情報は、括弧に入れず独立した文にする。

## 判断に迷うとき

迷ったときは自分だけで決めず、書き手に質問して確認する。次のような場面が該当する。

- 言い換えの候補が複数あり、文脈に最も合う語を選びきれないとき
- その語に定訳があるか判断がつかないとき
- 規則を適用すべきか、例外として残すべきか判断がつかないとき
